# Configuration reference

Every environment variable the app, its images and the deployment scripts read. Templates:
[`.env.example`](../.env.example) (development) and [`.env.production.example`](../.env.production.example)
(the bundled install's `.env` and the cloud `cloud.env`). The installer generates every secret for you.

In production the app validates its settings at start (`lib/env.ts`) and refuses to run with a missing secret,
a plain-text database or Redis connection, or mismatched public origins.

## Application

| Variable | Required | Description |
|---|---|---|
| `NODE_ENV` | production | `production` turns on the start-up validation, secure cookies and HSTS. |
| `DATABASE_URL` | yes | Runtime PostgreSQL URL. Production needs `sslmode=require`, `verify-ca` or `verify-full`; a transaction pooler on `:6543` needs `pgbouncer=true`. The bundled stack uses the least-privilege role `sworg_app`. |
| `DIRECT_URL` | no | Direct or session connection for `prisma migrate` (a role that owns the schema). Defaults to `DATABASE_URL`. Same TLS rule. |
| `REDIS_URL` | production | Rate limits. Production requires `rediss://`. |
| `AUTH_SECRET` | yes | Auth.js secret, 32+ characters. |
| `AUTH_URL` | production | The public origin. Must equal `NEXT_PUBLIC_BASE_URL`. |
| `NEXT_PUBLIC_BASE_URL` | production | The canonical origin for links in receipts, cards and email. Release images get it at start (placeholder replacement); your own builds compile it in. |
| `ALLOW_PLAIN_HTTP` | no | `1` allows an `http://` origin, for a LAN or trial install on plain HTTP. Never on the internet. |
| `NEXT_PUBLIC_HOSTED_BY` | no | Footer credit "Hosted by …". |
| `ALLOWED_ACTION_ORIGINS` | no | Extra hostnames allowed to call Server Actions (a CDN in front). Build time only; release images refuse it. |
| `TRUSTED_PROXY_IP_HEADER` | production | The client-IP header your edge overwrites: `x-real-ip` (bundled Caddy), `cf-connecting-ip` (Cloudflare) or `x-forwarded-for`. |
| `TRUSTED_PROXY_HOPS` | no | With `x-forwarded-for`, how many trusted proxies append to it (default 1). |
| `CRON_SECRET` | production | Bearer secret for `POST /api/internal/outbox`, the scheduler pass. |
| `SCHEDULER_MODE` | no | `in-process` (default): the app runs the scheduler pass every minute itself. `external`: a scheduler container, worker or cron calls the endpoint (every Compose stack and Render). |
| `OUTBOX_RETENTION_DAYS` | no | Days to keep delivered outbox rows (30). |
| `HEALTHCHECK_SECRET` | production | Bearer secret for `GET /api/health/db`. `/api/health` is open liveness. |
| `NEXT_SERVER_ACTIONS_ENCRYPTION_KEY` | production | Base64 of a 16, 24 or 32-byte key, stable across every container. Release images refuse to start without it. |
| `MFA_ENCRYPTION_KEY` | production | Base64 of 32 bytes; encrypts authenticator seeds. Never change it once in use. |
| `PAYMENT_SECRETS_KEY` | production | Base64 of 32 bytes; AES-GCM key for Razorpay and Stripe secrets at rest. Generated by the installer; back it up. |
| `SUPER_ADMIN_EMAIL` | yes | The first super admin. The installer creates it with the password you give; super admins are created, revoked and given passwords only on the server with `bash scripts/admin.sh`. An account with this address from before 0.7 is kept as super admin on upgrade. |
| `PWNED_PASSWORDS_CHECK` | no | `1` (default) refuses new passwords found in known data breaches, using Have I Been Pwned with k-anonymity (only a 5-character SHA-1 prefix leaves the server). `0` turns it off, for installs without internet access. |
| `EMAIL_FROM` | yes | Sender, `Name <address@verified-domain>`. Super admin → Settings overrides the email settings. |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE` | yes | Relay host, port (587, or 465 with `SMTP_SECURE=true`). |
| `SMTP_USER`, `SMTP_PASSWORD` | yes | Relay login. |
| `SMTP_SERVICE` | no | A Nodemailer well-known service instead of a host. |
| `SMTP_ALLOW_UNAUTHENTICATED` | no | `1` only for a private relay without authentication. |
| `S3_BUCKET`, `S3_REGION` | production | The private bucket. |
| `S3_ENDPOINT` | no | S3-compatible endpoint; HTTPS in production. |
| `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | no | Both or neither (an IAM role). |
| `S3_FORCE_PATH_STYLE` | no | `1` for Silo, MinIO and R2. |
| `AUTH_GOOGLE_ID`, `AUTH_GOOGLE_SECRET` | no | Google sign-in fallback (`GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET` also read). Super admin → Settings overrides. |
| `AUTH_GITHUB_ID`, `AUTH_GITHUB_SECRET` | no | GitHub sign-in fallback. |
| `AUTH_APPLE_ID`, `AUTH_APPLE_TEAM_ID`, `AUTH_APPLE_KEY_ID`, `AUTH_APPLE_PRIVATE_KEY` | no | Apple sign-in fallback: services ID, team ID, key ID and the `.p8` key with newlines as `\n`. |
| `BACKUP_PROVIDER`, `BACKUP_LAST_SUCCESS_AT`, `BACKUP_RETENTION_DAYS` | no | Backup posture shown in Super admin → Operations. `BACKUP_RETENTION_DAYS` also sets how long scheduled dumps stay (14 in the bundled stack). |
| `MIGRATE_ON_START` | no | `1` makes the backend role apply migrations before starting (Render). |
| `PORT`, `HOSTNAME` | no | Listening port and address inside the container (3000, `0.0.0.0`). |
| `NODE_EXTRA_CA_CERTS` | no | Extra CA for Node; the bundled stack points it at its private CA. |
| `NEXT_DEV_ALLOWED_ORIGINS` | no | Development only: extra hosts allowed to load dev assets. |

### Split hosting (website on Netlify)

| Variable | Where | Description |
|---|---|---|
| `DEPLOYMENT_MODE` | backend | `backend` serves only the API and Server Actions; `monolith` (default) serves everything. |
| `FRONTEND_GATEWAY_SECRET` | both | 64 hex characters shared by the website and the backend. |
| `BACKEND_ORIGIN`, `NEXT_PUBLIC_BACKEND_ORIGIN` | website | The backend's HTTPS origin. The frontend image gets it at start. |
| `FRONTEND_TRUSTED_IP_HEADER` | website | `x-nf-client-connection-ip` on Netlify, `x-real-ip` behind your own proxy. |

### Tests and demo data

`CI` with `ALLOW_INSECURE_PRODUCTION_TESTS=1` relaxes the TLS checks in CI only. `TEST_DATABASE_URL` points the
integration tests at a disposable database. `DEMO_PASSWORD` and `DEMO_MFA_SECRET` feed `npm run db:seed-demo`.

## Deployment (bundled `.env` and `cloud.env`)

| Variable | Default | Description |
|---|---|---|
| `SWO_REPOSITORY` | `SpaceWorks-Labs/SpaceWorks-Organization` | Repository the installer, updater and runner follow (a fork works). |
| `SWO_BACKEND_IMAGE`, `SWO_FRONTEND_IMAGE` | `ghcr.io/<owner>/spaceworks-organization-backend` / `-frontend` | Image names, derived from the repository owner. |
| `SWO_IMAGE_TAG` | `.spaceworks-version`, else `latest` | The release the stack runs. |
| `SWO_LAYER` | `none` | `none` plain HTTP through Caddy, `tls` automatic HTTPS, `proxy` your own proxy on `127.0.0.1:8080`. |
| `SWO_STORAGE` | `bundled` | `external` drops Silo for the `S3_*` bucket. |
| `PUBLIC_APP_BASE_URL` | | The public origin; becomes `AUTH_URL` and `NEXT_PUBLIC_BASE_URL`. |
| `SITE_ADDRESS` | | Caddy's site: `<domain>` for automatic HTTPS, `http://<host>` for plain HTTP. |
| `TLS_EMAIL` | | Let's Encrypt account email (`SWO_LAYER=tls`). |
| `HTTP_PORT`, `HTTP_PORT_BIND`, `TLS_HTTPS_PORT` | `80`, `0.0.0.0`, `443` | Caddy's published ports. |
| `API_BIND`, `API_PORT` | `127.0.0.1`, `8080` | Where the app listens for your proxy (`SWO_LAYER=proxy`). |
| `APP_BIND`, `APP_PORT` | `127.0.0.1`, `8080` | Where the cloud stack's app listens. |
| `POSTGRES_PASSWORD` | generated | Owner role `sworg` (migrations, backups). |
| `POSTGRES_APP_PASSWORD` | generated | Runtime role `sworg_app` (data only). |
| `REDIS_PASSWORD` | generated | Redis `requirepass`. |
| `MINIO_ROOT_USER`, `MINIO_ROOT_PASSWORD` | generated | Silo administrator. |
| `S3_APP_PASSWORD` | generated | Secret of the `sworg-app` storage identity, limited to the bucket. |
| `BACKUP_INTERVAL_HOURS` | `24` | Scheduled database dump and bucket mirror interval. |
| `SILO_IMAGE_TAG` | pinned | Silo release. |

## Scripts and images

| Variable | Used by | Description |
|---|---|---|
| `SWO_DIR` | `install.sh`, deploy job | Install directory (`/opt/spaceworks-organization`). |
| `SWO_INSTALL_REPOSITORY_PINNED` | installer | Set when the repository was chosen before download. |
| `SWO_STATIC_ENV_FILE` | wrapper | Settings file (`<install>/.env` bundled, `/etc/spaceworks-organization/cloud.env` cloud). |
| `SWO_UPDATE_INSTALL_DIR` | wrapper, updater | The install a staged updater works on. |
| `SWO_COMPOSE_BUILD_LAYER` | wrapper, `setup.sh --build` | `1` builds the backend image from the checkout. |
| `SWO_BUILD_KEY` | wrapper | Throwaway Server Actions key for local builds (generated per run). |
| `SWO_COMPOSE_PROJECT` | wrapper | Compose project (`sworg`, `sworg-cloud`, `sworg-smoke`). |
| `SWO_TLS_DIR`, `SWO_BACKUP_DIR` | compose | Certificate and backup directories (`./tls`, `./backups`). |
| `SWO_RUNNER_DIR` | `install-runner.sh` | Runner directory (`/opt/spaceworks-organization-runner`). |
| `SWO_DEPLOY` | GitHub repository variable | `true` enables the release workflow's `deploy` job. |
| `SWO_SCHEDULER_TARGET` | scheduler role | The pass endpoint (`http://backend:3000/api/internal/outbox`). |
| `SWO_TOPOLOGY` | ops role | `bundled` or `cloud`; the runtime-role check runs only for bundled. |
| `SWO_NEXT_DIR` | entrypoint | Where the web build is (`/app/.next`, frontend `/app/frontend/.next`). |
| `SWO_DISABLE_BUILD_CACHE`, `SWO_FRONTEND_STANDALONE` | Dockerfile | Image build switches. |
| `SWO_SMOKE_PORT` | `compose-smoke.sh` | The smoke test's edge port (18080). |
