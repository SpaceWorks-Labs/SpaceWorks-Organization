# Design

Space Works Organization follows the **Space Works brand** and **Space Works UX**, both from
[SpaceWorks-Design-System](https://github.com/SpaceWorks-Labs/SpaceWorks-Design-System):

- **Brand:** `tokens/tokens.css` and `docs/ui-brand-spec.md` set colour, type, logo and voice.
- **UX:** `docs/ux-spec.md` sets patterns P1–P30, layouts L1–L10 and the quality bar.

## Where things live

| File | What it is |
|---|---|
| `app/styles/tokens.css` | Every rule of the kit's `tokens/tokens.css` (colours, motion, reduced motion, kiosk/TV, charts) re-emitted as `--sw-*`, generated by `npm run design:sync`. **Never edit by hand.** |
| `app/styles/semantic.css` | Role names (canvas, panel, ink, primary, status pills…) pointing at kit tokens, in light and dark. |
| `app/globals.css` | The Tailwind 4 theme mapped onto the roles, type scale and motion curves; imports `app/styles/fonts.css` (the `@font-face` rules). |
| `app/styles/charts.css` | Chart roles: the five kit series, the edge and the ordinal ramp. |
| `app/styles/motion.css` | Keyframes, the colour-mode reveal and the reduced-motion rule; imports `motion-box.css`, `motion-overlays.css`, `motion-route.css` and `motion-search.css`. |
| `public/brand/` | Fonts, logo masters and icons copied unaltered from the kit. `brand/SOURCE.json` records the commit. `public/brand/motion/box-open.css` is the kit's generated box-open CSS, copied unaltered. |
| `components/ui/*` | Primitives: button, field, select, choice, dialog, sheet, menu, tabs, table, display, search field. |
| `components/brand/*` | Logo (with the box-open hover), box loaders, mood tiles and Patch (see "Patch, the mascot" below). |
| `components/motion/*` | Shared motion: presence, route transition and announcer, sliding indicator, collapse, stagger, skeleton. |

To update from the kit: `npm run design:sync` (it reads `../SpaceWorks-Design-System`, or a path you pass in), then
run the tests.

## Decisions

The kit's binding register is SpaceWorks-Design `docs/current-rules.md` (CR-*), synced at `5225d59` (v2.6.0; v2.6 adds rules only: §8.4, §15 and §16).

- **Colour mode (owner decision 2026-11-19, overriding CR-THEME-01's System option).**
  - Two choices only: **Light** (the default) and **Dark**. There is no System choice and the device's
    `prefers-color-scheme` is never read. A `system` value saved by an earlier build, or anything unknown, reads as
    Light.
  - The choice lives in the `swo.theme` cookie, mirrored to `localStorage` under the same key (`lib/colorMode.ts`,
    browser side `lib/colorModeClient.ts`). A session value keeps it working for the page when storage is blocked.
  - The server always paints from the cookie (no class for Light, `class="dark"` for Dark) and sets
    `meta[name=theme-color]` (`#FFF4E8` light, `#000000` dark). A nonce'd inline boot script in `<head>`
    (`COLOR_MODE_BOOT_SCRIPT`, nonce from the `x-nonce` header set by `lib/pageSecurity.ts`) only re-applies the
    saved choice (cookie, then the `localStorage` mirror) before first paint. Other tabs follow through the
    `storage` event.
  - Controls: `ColorModeToggle`, one 44px icon button in the site header and on organisation pages, after the kit's
    v2.5.1 theme toggle (panel fill, control-outline boundary, ink icon, ink boundary on hover, the global focus
    ring; the same in both themes). It is named "Dark theme", `aria-pressed` while Dark is on, and the sun or moon
    shows the theme that is on. `ColorModeMenuItem` is a "Dark theme" checkbox item in the app-shell and
    super-admin account menus, and the Appearance card on `/account` is a Light / Dark segmented control.
  - Every control calls the same switch (`setColorMode`/`toggleColorMode` in `components/providers.tsx`, which
    runs `switchColorMode` in `lib/themeTransition.ts`) with its own element as the origin. That file is a port of
    the kit's `motion/theme-reveal` (current rule v2.0.1): the new theme's page snapshot grows as a `clip-path`
    circle from the control over `--sw-theme-duration` (slow × 3 = 720ms) on the standard curve, the final frame
    held; a second press mid-reveal reverses the same mask; without View Transitions, or under reduced motion, the
    theme changes immediately. CSS: `app/styles/theme-reveal.css`.
- **Palette.**
  - `@theme { --color-*: initial }` removes Tailwind's default palette. The only colours available are the kit
    roles, plus `white`/`black`, which exist only for colour-picker handles and image overlays.
  - **Dark is one neutral black family (CR-DARK-01):** page `#000`, surface and sidebar `#0B0B0B`, panel `#141414`,
    hover `#1C1C1C`, line `#2C2C2C`, Cream text and Citron focus. The bright brand fills are the same in both
    themes. `semantic.css` derives emphasis (`#242424`) and danger-bg against black.
  - `.sw-dark-band` is a Deep Ink island on a light page only; on a dark page it rejoins the black family.
  - **Scrims** use the kit's scrim token: `bg-scrim/48` (Deep Ink in light, black in dark).
  - **Text is opaque (CR-OPACITY-01):** secondary text is `text-ink-muted`, never translucent ink.
  - **Status (CR-STATUS-01):** small marks (`Chip` success, warning and info) are the solid brand fill with its
    on-* label in both themes (`bg-success-mark text-on-success-mark` and so on). Large callouts (`Callout`) use the
    solid fill in light and the opaque soft fill with tone ink in dark (`bg-success-bg text-success-fg`). Accent,
    danger and neutral chips keep their soft, outlined and surface recipes.
  - **Disabled (CR-DISABLED-01):** `bg-surface text-ink-muted border-line`, with hover and press suppressed, never
    opacity. Prefer native `disabled`; an `aria-disabled="true"` control also ignores clicks, Enter and Space
    (`lib/ariaDisabled.ts`, installed once by the providers).
- **Charts (CR-CHART-01).**
  - Series are `--chart-1` … `--chart-5` (teal, orange, citron, sky, yellow), identical in both themes, from the
    kit's `--sw-chart-*` tokens (`app/styles/charts.css`). There is no sixth slot (`slotColor` clamps to five); fold
    the rest into "Other" (`--chart-muted`).
  - Contrast comes from `--chart-edge` (Deep Ink in light, Cream in dark): a 1px edge on filled marks (an SVG
    `stroke`, or `.sw-chart-mark` on HTML bars, segments and swatches) and a 4px casing under every 2px line.
  - Danger (`--chart-danger`) is never a series. Area washes and the hover band are opaque mixes, not alpha.
- **Type (CR-TYPE-01).**
  - **Outfit 400–700** (OFL, variable) for all reading and interface text; body is 400.
  - **Outfit 600** for product headings: `.text-h1`…`.text-h4`, base `h1`–`h4`, `.text-title`, `.text-overline` and
    figures.
  - **Gilroy ExtraBold (800)** for the display roles (`.text-display-*`) and public h1/h2 (`.sw-display-headings` on
    the site and organisation-page `<main>`). Gilroy ships only its free Light 300 and ExtraBold 800, each declared
    at its real weight; nothing is synthesised and Gilroy 400–700 are never requested.
  - **Unbounded** is for one accent phrase per public layout, never in staff chrome.
  - No monospace family: IDs, codes, secrets and JSON use Outfit with tabular figures (`.code-text`).
  - Email puts Outfit first in its stack. The receipt PDF stays in Gilroy: the kit's Outfit is a variable font with
    a Thin default instance, and pdf-lib cannot instance it.
- **Shape (CR-RADIUS-01).**
  - Controls are **10px** (`--radius-control`): buttons, single-line inputs, selects and nav items. Icon buttons
    stay round.
  - Multi-line fields and cards use 16px; tags and status pills are fully round.
  - No card shadows. Only overlays float (`shadow-float`).
- **Accent.** Teal by default. Public organisation pages may set their own with `accentStyle()` on a
  `.sw-accent-scope` root. Every derived value is contrast-checked to AA.
- **Shell dimensions (CR-SIDEBAR-01).**
  - Sidebar 256px: Citron in light, `#0B0B0B` in dark, a 20px inset, 44px items 4px apart, and a filled teal current
    item with `aria-current="page"`.
  - The navigation is text-only: no icons and no logos in nav rows, including the organisation switcher.
  - Content max width 1120. Gutters 16/24/36.
  - Breakpoints: 640/768/1024/1280. Below 1024 the shell becomes a top bar plus a sheet.
  - At most two sidebar count badges.
- **Motion (CR-MOTION-01).**
  - Tokens from the kit: `--sw-dur-fast/base/slow` = 120/180/240ms, and the curves `--sw-ease-standard`
    `(0.2, 0, 0, 1)`, `--sw-ease-enter` `(0.16, 1, 0.3, 1)` and `--sw-ease-exit` `(0.4, 0, 1, 1)`, plus
    `--sw-enter-y`, `--sw-pop-scale` and `--sw-pop-offset`. Reduced motion zeroes them; `.sw-kiosk`/`.sw-tv` zero
    the distances.
  - Tailwind: `ease-sw` is the standard curve (with `ease-sw-enter` and `ease-sw-exit`); durations are
    `duration-(--sw-dur-fast)` and so on.
  - Hover is colour only. Buttons sink to 0.98 on press, never under reduced motion.
  - The colour-mode reveal is the named 720ms exception (3 × slow on the standard curve, after the kit's
    `motion/theme-reveal`), and is instant under reduced motion.
  - **What exists and where** (ports of the kit's `motion/*` React folders, rewritten for the App Router):
    - **Logo:** `SpaceWorksLogo` draws the mark inline through `components/brand/AnimatedLogoMark.tsx`. Hover (mouse
      or pen) or keyboard focus of its link plays the box fold and open once (600 + 1600ms, a named exception). It
      never restarts in flight, never runs on touch or under reduced motion, and never changes size. The light mark
      keeps CR-LOGO-01's flaps (top-left and bottom-right `#006E63`, top-right and bottom-left `#FF7447`). Dark
      uses the reversed cream master, as the kit's SW-412 artwork does. The app-icon tile and tenant logos never move.
    - **Loaders:** `LogoLoader` (page or panel, the 4400ms loop, polite status, still open logo under reduced motion),
      `BoxSpinner` (16–24px, `mono` in the text colour) and `BoxArt` (the bare artwork). `BrandLoader`,
      `BrandPageLoader` and `Spinner` keep their names and draw the box, so `Button loading` shows it. The large
      keyframes load from `public/brand/motion/box-open.css` only where a box animates. The layout rules in
      `motion-box.css` show the still logo until that file arrives.
    - **Route transition:** `app/{dashboard,account,super-admin}/template.tsx` wrap the content area in
      `RouteTransition`, which fades the new page in with an 8px upward settle (slow, enter curve) and moves focus to
      its `h1` on a real pathname change only. The sidebar and top bar stay still. `RouteAnnouncer` (mounted once in
      the root layout) politely announces a page heading when Next.js's own announcer stays silent (same title).
      Scroll: Next.js already starts a pushed page at the top and restores the position on back and forward. Links
      that only change the query should pass `scroll={false}`.
    - **Overlays** (`motion-overlays.css`):
      - Dialog, sheet and drawer: 240ms in on the enter curve and 160ms out on the exit curve, with a scrim fade.
      - Menu, popover, select and tooltip: 120ms in and 90ms out.
      - Radix keeps a closing layer mounted for its exit; our own layers use `usePresence`.
      - `Dialog` (`components/ui/dialogRoot.tsx`) closes from the backdrop only when the press and the release
        both land on it. `Sheet`/`SheetContent` (`components/ui/sheet.tsx`) is the drawer (left, right) or bottom sheet.
    - **Toasts** (`components/feedback/ToastProvider.tsx`, timing in `toastTiming.ts`):
      - 180ms in and 120ms out, up to three at once, with a close button.
      - Each lasts 8s, paused while hovered or focused. Errors stay until dismissed and are announced through
        `role="alert"`; everything else goes through a polite status region.
    - **Sliding indicator:** `useSlideIndicator` moves one box with transform only. It is used by `TabsList` and
      `NavTabs` (the underline) and by the sidebar's `SlidingNav` (the filled current item). It is instant under
      reduced motion, and pill-styled tabs keep their own highlight.
    - **Page pieces:**
      - `Collapse` and `Disclosure` (grid rows with a fade, 180 to open and 120 to close, closed content unmounted).
      - `StaggerGroup`: the first eight children rise once on first mount; pass `enabled` from the
        organisation's delight setting.
      - `RevealRoot` (`components/motion/RevealRoot.tsx`, the one shared copy): `[data-reveal]` blocks rise once as
        they arrive (640ms, enter curve); nothing hides without script or under reduced motion.
      - Tenant logos never move: `OrgLogo` carries `data-tenant-logo`, and the route transition, stagger and reveal
        leave any block holding one still (a stagger child then lifts only its `data-stagger-enter` parts).
      - `Skeleton`: a still surface with the small box, no shimmer.
      - `ProgressBar`: scales its fill with transform, never width.
      - `SearchField` (`components/ui/search-field.tsx`): the magnifier nudges on focus, swaps to the box while
        loading, and has a clear button, Escape to clear and an optional shortcut hint.
    - Hover never animates on touch: Tailwind's `hover:` already sits inside `@media (hover: hover)`, and the
      plain CSS hovers here are gated the same way.
- **Copy.** Sentence case, en-GB, and buttons named after their action. No "Oops", and no exclamation marks
  on errors.

## Member cards

- **One drawing, three outputs.** `components/cards/CardCanvas.tsx` (browser) and `lib/cards/layout.ts` (PDF and
  PNG) draw the same boxes, palette, template decor and layers. Cards are CR80 (85.6 × 54 mm), landscape or
  portrait, with four presets (Community, Corporate, Night, Student) and fourteen templates
  (`lib/cards/design/templates.ts`: Standard, Corporate, Minimal and Lanyard badge in both orientations, then
  Aurora, Kasavu, Ribbon, Confetti, Midnight gold and Sunrise). Template decoration stays inside the safe area:
  no stripes along the card's edges (`tests/unit/card-templates.test.ts`).
- **What a card carries.** Fronts: the organisation and its logo, the photo (a hairline round it; without one, the
  initials on a soft tint of the accent, at 4.5:1), the name largest (shrinking to half size and two lines, then an
  ellipsis), role, units, plan, the card number in tabular figures, "Valid until …" and the QR code on a white tile
  with a quiet zone and "Scan to verify" (`lib/cards/design/qrTile.ts`, `showQrCaption`). Role, plan, number and
  validity stay on one line: shrunk to three quarters at most, then cut with an ellipsis. Backs
  (`lib/cards/design/sides.ts`): plan, number and validity, the organisation's website, email and phone
  (`{contact}`), an authorised-signatory line and how to check the card, beside the symbol.
- **Which design a card uses:** the member's primary role design, else the plan's, else the organisation's.
- **Approval.** The designer autosaves a draft. Members' cards keep the approved design until the owner chooses
  Approve and publish; managers can discard a draft but not publish it. The bar under the designer's header says
  which state the design is in.
- **Layers** (`lib/cards/design/layerTypes.ts`, normalised in `layerNormalize.ts`): up to 60 per side, front and
  back alike. Kinds: text, picture, rectangle, ellipse, line (solid, dashed, dotted), shape (triangles, polygons,
  star, burst, heart, arrow, chevron, shield, badge, speech bubble, cross, top and bottom bands — wave, curve,
  chevron, diagonal, ribbon — corners, rounded frames and a checked custom path), icon (a Lucide subset copied as
  paths, `icons.ts`), the card's own QR code, the card number as a Code 128 barcode (`barcode.ts`) and a photo frame
  (circle, rounded, hexagon or square, initials when there is no photo). Every layer is placed, sized, turned and
  optionally flipped in millimetres, can join a group (`groupId`) and be hidden or locked; its opacity fades each
  part it draws. Shapes take a solid fill or a linear or radial gradient (2–5 stops), a vector texture (dots,
  stripes, grid, waves), an outline and a hard shadow. Text takes `{name}`, `{role}`, `{plan}`, `{number}`,
  `{validUntil}`, unit, `{organisation}` and contact placeholders, a case (upper, lower, title), letter spacing, line
  height, an arc (`curve`), an effect (highlight, outline, hollow, shadow) and auto-fit. Pictures take crop and zoom
  about a focal point, a mask, corner rounding, greyscale, brightness, contrast, saturation and blur (baked into the
  bitmap by sharp before embedding, `lib/cards/artPrepare.ts`, so the PDF and PNG carry the same pixels), a shadow
  and alt text (read out in the designer; PDFs are untagged, so it isn't exported). One set of outlines
  (`shapes.ts`, `paint.ts`, `path.ts`) feeds the canvas (`components/cards/layerArt/`), the PNG
  (`lib/cards/svgVector.ts`) and the PDF (`lib/cards/pdfVector.ts`: even-odd paths, clipping, axial and radial
  shadings); text is always shaped outlines. `tests/unit/card-parity-layer-kinds.test.ts` checks every kind on both
  sides. Older designs read back unchanged; unknown shapes, icons outside the set, bad paths and pictures that
  aren't the organisation's own `member-id-artwork` are dropped. `order` stacks built-in items and layers together,
  bottom first, under a background colour and picture (fill or fit, with strength).
- **Type on cards.** Gilroy Light and ExtraBold by default, or any of the 66 open-licence families in
  `public/fonts/card` (`lib/cards/fontCatalog.ts`, synced by `scripts/sync-card-fonts.mjs`, licences in
  `public/fonts/card/LICENSES.md`), for layers and for each built-in text item. Every face falls back to OFL Noto
  Sans (extended Latin and ₹), Noto Sans Malayalam and Noto Sans Devanagari. The browser registers each family
  with unicode ranges (`components/cards/cardFonts.tsx`); the server loads a family the first time a design uses
  it. Long names shrink until they fit the room kept for them, measured with real shaping on the server and with
  canvas metrics in the browser.
- **Colour.** Card colours are brand keys, the organisation's accent or any colour of the organisation's own; every
  built-in text colour keeps 4.5:1 against what it sits on, and Workshop Orange is a fill only. Layer colours are
  as chosen; print-economy mode turns them black or white.
- **The designer** (Settings → Cards) is three panes from 1280px: a left pane with Design (templates — the
  organisation's own under "Your templates" — orientation, numbers, background, built-in items), Elements and Fields
  tabs; the card to scale with rulers, zoom (fit, 50–400%) and pan (Space+drag); and the Position and Arrange panels
  with the selected layer's inspector above the layers list. Below 1280px they stack, card first. Front and back are
  edited the same way (a side switcher, and "Both sides" side by side on wide screens), with "Copy layout to the
  other side" and "Duplicate onto the other side"; the clipboard works across sides.
- **Editing.** Click, Shift-click or drag a marquee to select; drag to move, eight handles to resize (Shift keeps the
  ratio; pictures keep it by default) and a knob to turn (Shift: 15° steps). Moving snaps to the card edges, centre
  lines, safe zone, custom guides dragged from the rulers and other layers' edges and centres, with pink guide lines
  and spacing labels; Alt turns snapping off. Grid, bleed and safe-zone overlays toggle. Align, distribute, group,
  order, flip, duplicate, copy and paste, copy style, lock and hide are buttons as well as shortcuts (`?` lists
  them), so nothing needs a pointer. Arrow keys nudge 0.5 mm (Shift: 5 mm). Every change is one undo step. Turning
  the card re-lays both sides' layers in proportion.
- **Elements** (`lib/cards/design/library/`): shapes, bands and borders (top and bottom headers and footers, side
  strips, corners, frames), badges and stickers (seal, ribbon banner, Member, Verified and Staff tags with editable
  words), icons, dividers, QR code and barcode, photo frames, text styles, gradients and patterns, in the brand
  kit's colours, plus the brand kit's logos. Multi-layer elements arrive grouped. The Fields tab inserts
  placeholders and shows each one's value for the sample or preview member.
- **Colour tools.** Every colour field offers the brand colours first, then the design's own colours ("Document
  colours"), the quick swatches, an eyedropper (the browser's EyeDropper where it exists, else a pick from the card)
  and a picker; "Replace this colour everywhere" swaps one colour across both sides.
- **Brand kit** (`CardBrandKit`, `lib/cards/brandKit.ts`): logo variants from the organisation's own uploads, up to
  12 colours (extracted from the logo by `lib/cards/paletteQuantize.ts`, edited by hand, each with AA contrast
  hints) and up to 4 preferred card fonts. Brand logos placed on a card are copied into its artwork first
  (`app/actions/card-artwork.ts`), because cards draw only `member-id-artwork`.
- **Logo maker** (Settings → Profile, `lib/logo/`): initials or a short name, a shape (circle, rounded square,
  hexagon, shield, badge), preset or brand colours, a card font and an optional icon, previewed live; saving draws
  the text as font outlines, rasterises with sharp and stores it through the ordinary logo upload path (audited
  `ORGANISATION_LOGO_GENERATED`). Uploaded logos can be cropped and zoomed square first.
- **History, preview and export.** Drafts are kept as versions (one per 10 minutes) and every approval too, 30 per
  design; any can be restored to the draft (the owner still approves it). "Preview with a member" shows a real
  member from the viewer's own scope (name, role, number, units, plan, validity, photo only; sample answers). The
  editor downloads the saved draft as a PNG of one side or a PDF, optionally print-ready with 2 mm bleed and crop
  marks, through the render slot.
- **Deliberately left out:** stock photo libraries, AI generation, background removal on member photos, real-time
  co-editing and comments, and video or animation on cards.
- **Delight moment.** A card issued in the last two minutes rises into place on the member page and one Citron and
  Sky Blue sweep crosses it, once per tab (`components/cards/cards.module.css`). With reduced motion the card
  simply appears.
- **The holographic card** tilts towards the pointer or the phone and flips to its back; with reduced motion it
  stays flat and the flip is an instant swap.
- **`/verify/[token]`** leads with the verdict (Current member, Renewal due, Not started yet, Not a current member,
  Membership revoked), each a colour plus an icon plus words, then the name, plan, valid-until and card number.
  It never shows contact details and is not indexed.

## Landing page (`/`)

Built to product rules §12.1 in the style of the Space Works hub landing and the design-system site
(v2.5.1). It is on by default, and `LANDING_ENABLED=false` makes `/` follow the data (§12.2,
`lib/features/landing.ts`).

- **Order:**
  - Hero: the product name, the promise and a screenshot that follows the theme.
  - Membership story: join → approve → pay → card → renew, beside a pinned sample record.
  - Sample member cards ("Cards your members carry", `components/marketing/CardShowcase.tsx`): the Space Works team
    on SpaceWorks cards (the real Space Works symbol as the logo, SWK-0001 to SWK-0006), each in a different
    built-in design. They are drawn by the product's own renderer, not by hand: `npm run landing:cards`
    (`scripts/render-landing-cards.ts`, data in `lib/marketing/sampleCards.ts`) writes
    `public/landing/cards/*.webp`; rerun it and commit the images when the samples or the renderer change.
  - **The cards drift (owner decision, 2026-11-19).** The one loop outside a loader: the set twice in a track that
    moves by half its width in 54 s, linear, transform only (`CardDeck`, `cardMotion.ts`). A Pause motion button
    (`aria-pressed`, WCAG 2.2.2) stops it, and so do a pointer or keyboard focus on the cards, the section being off
    screen and a hidden tab. The copy is `aria-hidden`, so each card is announced once. Reduced motion shows the
    still row instead (fanned from 1024px, scroll-snap below) and hides the button. They are SpaceWorks's own
    samples, not a tenant's cards, so the rule that tenant logos never move doesn't apply.
  - One headline per feature area, each linking to `/features#<area>`. The detail lives on `/features`
    (`lib/features/catalog.ts`).
  - Screenshots in light and dark.
  - Self-hosting on a rounded Deep Ink island (`.sw-land-island`; on a dark page it rejoins the black family).
  - Open source, questions, and a closing call to action.
- **Links:** GitHub, the latest release (`RELEASE_VERSION` in `lib/openSource.ts`, which a test keeps equal to
  `VERSION`), the install one-liner, `/docs`, `/features`, the AGPL licence and the changelog. They appear in the
  header ("Project" popover) and the footer.
- **Grounds:** Warm Cream with the kit's quiet masked symbol pattern. Workshop Orange is used only for the primary
  call to action, and Unbounded for one phrase.
- **Motion** (`components/marketing/landing.css`, kit tokens only):
  - A non-blocking cold-start splash plays once per page load: the box opens (the kit's 1600 ms `once` artwork),
    then flies into the header's Space Works mark (`components/marketing/splashFlight.ts`: transform only, 480 ms on
    the enter curve) while the canvas fades; the header mark is hidden until it lands. With no mark on screen (the
    phone header, a scrolled page) or no JavaScript the layer fades in place (240 ms, exit curve). It never takes
    input, and reduced motion draws nothing.
  - The logo opens on hover and focus.
  - Sections reveal once (`data-reveal`, 640 ms, enter curve), with no scroll scrubbing and no loops outside a
    loader, except the sample cards' drift (above).
  - Reduced motion and phones get a plain static page.
- **Objects:** every sample record or card is labelled as a sample, and the page makes no customer or usage claims.

## Member portal (`/account`)

- **Wallet first.** `/account` is the membership wallet: one card per organisation (logo, member number,
  unit, role chips), one row per plan with a status chip, a single sentence on where it stands ("Valid until
  31 Mar 2027 · 20 days left") and only the actions that apply now. Pay is the accent button; Renew is
  primary; Cancel renewal is ghost; Leave is a quiet danger link behind a confirmation.
- **Tabs.** Memberships, Profile, Data and privacy, Organisations (team roles), Security. Each membership's
  page (history, details, receipts) and the pay page sit under Memberships.
- **History** reads as a timeline per term: dates and amount, then each change in plain words
  ("Active · Payment received").
- **Irreversible steps** (leaving, erasure) always confirm, say what stays (payments) and what doesn't.
  Approving an erasure asks the manager to type ERASE.
- **Slots.** `components/portal/Slots.tsx` reserves the card (P6) and receipts (P7) spots, so they plug in
  without a layout change.

## Public page editor (Settings → Public page)

- **Two columns** from 1280px: the form on the left, a sticky live preview on the right (inert, rendered by
  the same `PageSections` component as `/o/[slug]`, inside the page's own accent scope). Below that width
  the preview follows the form.
- **Preview toolbar.** Light or dark, whatever the app's theme (`preview.module.css` sets that mode's kit values
  and re-points the role aliases, the way `.sw-dark-band` does), and desktop or a 375px phone frame. Sections
  lay out by container queries (`@container` on the page and the frame, `@xl`/`@2xl`/`@4xl`/`@5xl` for
  sm/md/lg/xl), so the phone frame reflows like a phone. Videos stay placeholders and nothing navigates.
- **Sections** are collapsible rows: a drag handle (native drag and drop, with a drop line), show/hide switch,
  move up and down buttons (and Alt+Up/Alt+Down on the name), duplicate and remove (confirmed when the section has
  content). Moves are announced once in a polite live region. One row is open at a time; errors from the server
  mark the row "Needs attention" and the field.
- **Adding** opens a dialog grouped Welcome, Membership, People and story, Media, Information, with a line on what
  each section does. A page has one hero; it leads the page when it is the first visible section.
- **Templates** (Club, Alumni association, Professional association, Makerspace or community, Sports club,
  Cultural society; `lib/publicPage/templates.ts`) replace the sections with placeholder copy and keep the accent
  and cover; a draft with content asks first.
- **Draft and publish.** A sticky bar holds Publish, Save draft, Discard changes and Unpublish, with status
  chips for published, unsaved changes and unpublished draft. Leaving with unsaved changes asks first.
- **Accent check.** Presets plus the custom picker; the line under it gives the button contrast against the
  light page and the label contrast, and warns below 3:1.

### On the public page (`/o/[slug]`, `components/public/sections/*`)

- **Look:** the product landing's quality bar. Spacing separates sections (no bands), Gilroy ExtraBold display
  headings, a readable measure for prose, flat 16px panels and colour-only hover. The organisation's accent comes
  through `accentStyle` (AA-checked), and the page works in both themes and at 375px.
- **Top:** a leading hero (split, centred or cover) or the plain cover, logo and name. The tagline is the layout's
  one Unbounded phrase. The top holds the tenant logo, so it never moves.
- **Motion:** sections reveal once (`data-reveal` in `RevealRoot`) and enter with the route. Nothing loops and
  nothing scrubs with scroll. The sample card carries the organisation's logo, so it never moves; only its words
  reveal. With the organisation's delight switch on, stat and testimonial lists rise in once (`DelightList`).
  Reduced motion gets the static page.
- **Call to action, ink tone:** a rounded Deep Ink island (`.sw-dark-band`); on a dark page it rejoins the black
  family.
- **Empty sections** are left out for visitors and explained in the preview. FAQs use native `<details>`, so they
  work without script.
- **Videos** use a click-to-play facade: no frame and no request to YouTube or Vimeo before a visitor presses
  play.

## Patch, the mascot

Patch is the Space Works painted wolf from SpaceWorks-Design `mascot/` (read its README before changing any of
this). The box symbol stays the logo everywhere; Patch is never put inside or beside it.

- **Files.** `public/brand/patch/` holds `patch.webp` (the hero pose) and `patch-poses.webp` (the eight
  sneeze-loop frames side by side), both made by `node scripts/sync-patch.mjs [path-to-SpaceWorks-Design-System]` from
  `mascot/original/`, which only reads the design repo. The walk sheets `patch-walk-right.webp` and the
  approved left-facing `patch-walk-left.webp` are copied unchanged from SpaceWorks-Events. Patch is never
  recoloured, mirrored, stretched, outlined or shown past its native size.
- **Component.** `components/brand/Patch.tsx` with three poses, drawn by `app/styles/patch.css`:
  - `idle` breathes, blinks and twitches each ear (frames 1–4 on the kit's seven-second timing, no sneeze);
  - `sneeze` plays the sneeze (frames 5–8) once, then idles;
  - `walk` trots in place on the walk cycle.
  Patch carries clear space of a quarter of its badge as padding, is decorative (`aria-hidden`) unless given a
  `label`, and rests on its first frame under reduced motion.
- **Where Patch appears, and why.**
  - **404** (`app/not-found.tsx`): the interactive pet, the page's one bold moment.
  - **First-time empty lists** (`EmptyState patch`): no organisations yet (dashboard), no plans yet, no
    members yet, no payments yet, and no public organisations yet (directory). Filtered or searched empty
    lists keep the Sleepy mood tile, so Patch only greets a list that has never had anything in it.
  - **Loading** (`BrandPageLoader`, dashboard routes): Patch walks in place above the hopping dots. In dark
    mode it sits on a Warm Cream disc, because its dark outline disappears on Deep Ink.
  - **The sneeze vote**, saved for moments when the community decides together: an organisation's application
    approved (`/dashboard/[org]/application` once it is active), and a manager approving a member's
    application (the member page's Memberships panel). Each sneezes once.
  - Not on organisation-branded public pages (`/o/…`), which carry the organisation's brand, not ours.
- **Bold moments.** Patch counts as a layout's one bold moment, so a screen with Patch has no Unbounded phrase
  and no Workshop Orange flap. None of the screens above has either.
